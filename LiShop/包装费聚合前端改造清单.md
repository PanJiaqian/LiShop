# 包装费聚合前端改造清单

> 适用项目：`front\LiShop\LiShop`
>
> 对应后端改造：购物车结算阶段按母商品聚合包装费

---

## 1. 改造目标

前端需要从“逐条商品各自带包装费”的旧展示方式，切换为“购物车结算阶段按母商品聚合包装费”的新口径，确保：

1. 购物车列表页、结算区、订单页金额口径一致
2. 前端正确消费后端新增的聚合包装费字段
3. 移除仍依赖旧包装字段的展示逻辑，避免误导用户

---

## 2. 改造清单

## 2.1 购物车页 `pages/cart/index.vue`

- [x] 接入 `/api/cart/calculate` 返回的 `items[].item_amount`
- [x] 接入 `/api/cart/calculate` 返回的 `items[].item_original`
- [x] 接入 `/api/cart/calculate` 返回的 `items[].package_fee_group_key`
- [x] 接入 `/api/cart/calculate` 返回的 `items[].package_fee_selected_package_id`
- [x] 接入 `/api/cart/calculate` 返回的 `items[].package_fee_is_group_owner`
- [x] 每次重新结算前先清空旧的聚合包装费回填状态，避免勾选切换后的脏数据残留
- [x] 行价格显示优先使用结算接口回填后的 `item_amount`
- [x] 行包装费标签仅在当前条目为整组包装费承担条目时显示
- [x] 结算区文案从“商品总价”调整为更准确的“订单原价”
- [x] 保留 `total_package_fee` 展示，但语义明确为“订单中包含的聚合包装费”

## 2.2 订单页 `pages/order/index.vue`

- [x] 移除旧的 `package_capacity`、`package_price` 依赖展示
- [x] 订单明细改为展示更稳定的商品备注、品号等真实字段
- [x] 补充行小计展示，避免单价与合计理解不清
- [x] 统一订单详情页的金额展示口径，避免沿用旧包装规则描述

## 2.3 风险说明

- [x] 用户侧订单接口 `/api/user/orders/*` 已补充聚合包装费辅助字段，订单页可展示逐条聚合包装费与订单总包装费
- [ ] 当前订单页已展示逐条聚合包装费和总包装费，但尚未展开 `package_fee_groups` 的完整分组明细；如后续需要显示“候选包装规则试算过程”，仍需补充更细的前端展示区块

---

## 3. 实施顺序

1. 先改购物车页回填与行显示
2. 再改订单页，移除旧包装字段依赖
3. 最后做联动检查，确认结算页与订单页文案一致
